# Context Map

One product, two bounded contexts, built as a modular monolith. Each context owns its event store and its language; they integrate only through durable in-process catch-up subscriptions over each other's published events (producer-owned schemas, tolerant readers behind an anti-corruption layer). There is deliberately no shared kernel: a type needed by both is duplicated in each.

## Why two contexts

The product is built as small, independently replaceable blocks: any one block can be rebuilt or swapped out with minimal blast radius. The seam discipline — producer-owned events, tolerant readers, no shared kernel, nothing from the other side trusted as truth — is what keeps a block swappable.

The boundary is also linguistically honest, because the two models ask different questions with different evidence. The downloader asks _"is this copy the release that was requested?"_ — judged on structural, tag-blind evidence, cheaply at search time (match confidence) and authoritatively after download (validation). The importer asks _"what canonical album is this directory, and how should it enter the library?"_ — judged on tag agreement (beets' distance, decomposed into named penalties), a dialect that is beets-shaped by charter because beets is the library's system of record. Distance is request-blind: delivery hints pin its search, never its verdict. The two quality scalars share a [0,1] shape with opposite polarity and must never share a model.

The boundary has accepted costs, on record. The importer re-derives identification the downloader already performed, because hints are never trusted as truth. And files are checked against metadata on both sides — a principled duplication, not an accidental one: the downloader validates the **unfixable** axes (does every file decode; do durations and track count match), because a bad copy's only remedy is the next candidate; the importer judges the **fixable** axes (tags, canonical identity), because repairing descriptions is its job. The residual structural overlap in beets' penalties is the tripwire that catches whatever downloader validation missed.

Doctrinal grounding, the canon's prior, and the pitfall checklist this split must keep passing: `docs/research/bounded-contexts-vs-modules.md`.

## Contexts

- [Downloader](./packages/downloader/CONTEXT.md) — given a download request and a quality policy, finds, downloads, validates, deposits, and (on failure) retries the best-matching, highest-quality copy of a release across pluggable sources
- [Importer](./packages/importer/CONTEXT.md) — proposes beets-powered metadata matches for delivered directories, auto-applies confident ones into the library, queues uncertain ones for human review; beets is the library's system of record
- [Web](./packages/web/CONTEXT.md) — **not a bounded context**: the SvelteKit BFF and browser UI. Presentation-only, but it owns a real vocabulary of its own (the copy register, the attention queue, the timeline) plus the access-control model — hence its own glossary

## Relationships

- **Downloader → Importer**: the downloader publishes `acquisition.fulfilled` (in its own wire vocabulary: acquisition, target, candidate, location) on its outbound feed; the importer's intake consumer (`seam:acquisitions`) translates it at its anti-corruption layer into a native submission, treating the download's id and the delivered copy as opaque foreign provenance.
- **Importer → Downloader**: the importer publishes `release.verdict` (the download's id, the delivered copy, verdict, reasons — never its internal resolution verb); the downloader's verdict consumer (`seam:verdicts`) translates it into an external validation failure, which re-enters the retry ladder. The full round trip — fulfilled → import → verdict → re-search → fulfilled again — is **the revival loop**.
- **Correlation**: one story id (correlation id, W3C trace-id format) is minted at the outermost trigger — the web BFF for user actions — and _adopted_ across the seam, never re-minted or translated by the ACL. Correlation = story, causation = immediate parent, everywhere. (Beware: Axon's docs invert these names.)
- **Contexts → Web**: no events. The web calls each module's single wire-shaped facade in-process, may read both to compose a view, and may dispatch a command to either — but never sequences a business workflow across both. Its cross-context joins (timeline, attention queue) are web-owned and introduce no contract between the contexts. The join key between a download and its import is the **download's id** (wire name `acquisitionId`), not the correlation id.

## Seam vocabulary

Named concepts of the integration mechanism (defined in `cross-module-delivery` / `operation-correlation` specs): **catch-up subscription**, consumer-owned **checkpoint**, **at-least-once ordered delivery**, **notify-then-poll** (the wakeup is a lossy latency hint; the poll alone guarantees delivery), **poison-event policy** (`halt` or `park`), **the event store is the outbox**, **tolerant reader**, **contract gate** (additive-only; a breaking change is a new event type), **frozen fixtures**.

## Cross-context homonyms
