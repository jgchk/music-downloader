# Design — decider-properties

## Context

Research verdict #4 (`docs/research/automated-quality-function.md`): model-conformance PBT
for the event-sourced core, on the ShardStore precedent. The grilling resolved the central
shape question: the published ShardStore pattern (complex stateful implementation checked
against a simple executable model) assumes an implementation/model *gap* — but this repo's
deciders are already pure functions over immutable values, so a per-aggregate reference
model would be a near-duplicate that drifts, and worst-case gets "fixed" into agreement
with a buggy decider (the self-grading problem again). Therefore: **oracle properties and
invariants over generated command sequences**, no parallel models — except where a genuine
gap exists (the event store's optimistic concurrency, a stretch task).

## Goals / Non-Goals

**Goals**

- Stateful property suites for every aggregate in both packages, in the vitest unit tier,
  inside `pnpm check`.
- Mechanized: never-throws (decide total-as-Result), evolve totality, fold determinism,
  prefix-fold consistency, upcaster round-trips through the real store codec.
- CI-deterministic: pinned seed; failure output carries seed + counterexample path for
  exact replay.

**Non-Goals**

- No parallel decider reference models. No property tests for adapters/UI (mutation gate
  and contract tiers own those). No model-checking toolchain (TLA+, dst) — named as the
  escalation if a concurrency defect ever slips past this tier. No shrinking-time budget
  games: default shrinking stays on.

## Decisions

### D1 — Properties as relations/invariants, not second implementations

Each aggregate gets: an `arbCommand` (valid + boundary + deliberately-invalid payloads) and
generated sequences driven through real `decide`/`evolve`. Assertions are universally
quantified relations: reachable-state invariants (the ones types can't express — e.g. a
settled lifecycle never re-enters an active phase), decide-returns-Result-never-throws
(the port-contract Liskov clause, mechanized), evolve-total (every event constructible from
the stream's schema), fold determinism, and prefix-fold consistency (the reactor contract:
`fold(events[0..n]) + evolve(event[n+1]) ≡ fold(events[0..n+1])`).

### D2 — Upcaster round-trip is a codec property, not a unit fixture

v1 event JSON generated by arbitrary, serialized through the real store codec, upcasted by
the real registry, then evolved — asserting the v2-documented semantics hold. This pins the
upcaster contract (`ReviewResolved` v1→v2 precedent) against *generated* v1 shapes, not
just the two fixtures someone wrote.

### D3 — Placement and budget

Property files live beside each aggregate's existing unit tests (`*.property.test.ts`),
run in the normal vitest pass. Default `numRuns` (100) per property; the whole tier must
stay inside the seconds-order `pnpm check` budget — if a suite breaches it, `numRuns`
drops locally and a CI-only env bump (`FC_NUM_RUNS`) raises it there. Seed pinned in CI
(fixed constant in config) so CI never flakes; local runs may unpin for exploration.

### D4 — Coverage interaction

Generators and property helpers are test code and outside the 100% production-coverage
denominator; no waivers needed. Properties *supplement* example tests — BDD example tests
remain the readable specification (testing.md register); properties are the adversarial
sweep behind them. Neither replaces the other.

### D5 — The one reference model (stretch)

Event-store optimistic concurrency: an in-memory map+version model, fast-check
model-based commands (append/read with expected-version), asserting the SQLite
implementation agrees with the model on success/conflict outcomes. This is the seam with a
true implementation/model gap; it is a stretch task because the store already has a
conflict-behavior test suite — the model run generalizes it.

## Risks / Trade-offs

- **Flaky-CI reputation of PBT** — answered structurally: pinned seed means CI is
  deterministic by construction; new counterexamples only enter via code or generator
  changes.
- **Generator drift** (arbitraries not covering new commands/events): closed unions +
  exhaustiveness checks make an unhandled variant a compile error inside the arbitrary
  builders where feasible; otherwise a completeness property (every schema variant is
  generable) pins it.
- **Wall-clock creep**: budget in D3, measured at adoption, recorded here.
- **A property failure can be cryptic** — mitigation: each property's assertion message
  names the violated invariant in constitution language, and the seed/path repro line is
  the first thing printed.

## Migration Plan

Pure addition to the test tiers; no runtime surface, no migration. If a property finds a
real defect during adoption, the fix ships red-first inside this change as `fix:` with
whatever spec delta the defect implies.

## Open Questions

- None blocking. Which aggregate goes first (downloader Acquisition vs importer Import) is
  decided at implementation by the mutation gate's survivor data, per the proposal's
  sequencing rationale.
